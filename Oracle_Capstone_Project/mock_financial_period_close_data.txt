PURPOSE
-------
This file contains realistic mock scenarios for multiple financial periods
across multiple ledgers. Each period entry documents the ledger state, current
period statuses, any blocking transactions, and whether the period CAN or
CANNOT be closed. Scenarios are grouped into two sections:

  SECTION A — Periods ABLE to Close   (clean state, no blockers)
  SECTION B — Periods UNABLE to Close (blocked state, with root-cause details)

The agent should use these examples to understand:
  1. What a "clean" ledger state looks like before initiating a close.
  2. What specific blocker conditions prevent a period from closing.
  3. Which module owns each blocker and what the corrective next step is.
  4. The correct sequence: Costing must close before General Ledger (GL).

PERIOD CLOSE SEQUENCE (for reference)
--------------------------------------
  Step 1 — Resolve all Costing/PO Receipt transaction errors.
  Step 2 — Close the Costing period (ApplicationId: 10078).
  Step 3 — Resolve all AP unaccounted / not-transferred-to-GL invoices.
  Step 4 — Resolve all AR unaccounted / not-transferred-to-GL transactions.
  Step 5 — Resolve all Inventory transactions not transferred to Cost Mgmt.
  Step 6 — Close the General Ledger (GL) period (ApplicationId: 101).
